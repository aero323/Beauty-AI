# SalesBoost AI

面向总部培训团队、区域培训负责人和门店管理者的培训管理后台。围绕「内容建设 → 任务分发 → 学习与考核 → 问题识别 → 整改复盘」组织工作，覆盖课件、题库、AI 陪练、媒体素材和组织档案。

**当前版本：v0.1.0 · 2026-09-08 — 培训巡检与整改闭环。**

> 本仓库是可运行的前端交互原型。任务、人员、AI 分析与管理指标以演示数据为主，尚未接入生产身份认证、真实消息服务或持续运行的后端 Agent。培训巡检的规则计算和整改状态流可在本地完整验证。

## 快速开始

建议使用 Node.js 22 或更新版本，配合 npm。项目不需要配置模型 API Key 即可运行演示。

```bash
git clone https://github.com/aero323/Beauty-AI.git
cd Beauty-AI
npm ci
npm run dev
```

打开终端输出的本地地址，默认是 `http://localhost:3000`。若默认端口已被占用，Vite 会尝试其他端口；也可以显式指定：

```bash
npm run dev -- --port 4176
```

生成与预览生产构建：

```bash
npm run build
npm run preview -- --port 4176
```

开发服务默认监听所有网络接口。只需要本机访问时，使用 `npm run dev -- --host 127.0.0.1`。

## 培训巡检 Agent

### 使用入口

以「总部培训师」角色进入左侧 **培训巡检**。桌面端左下角提供角色切换器，手机端通过顶部导航选择工作台。区域演示固定使用雅加达南区。

| 视图 | 管理问题 | 主要操作 |
| --- | --- | --- |
| 全国巡检 | 哪些区域负荷过高，哪些事项需要总部介入？ | 比较区域人均/P90 负荷、异常人数、复核压力，下钻问题 |
| 区域计划 | 同一批 BA 是否被重复安排或集中压任务？ | 查看周时间轴与逐人明细，调整日期、频次、耗时和分配对象 |
| 整改跟踪 | 谁负责、何时处理、问题是否真的解决？ | 查看证据、提交整改计划、申请例外、提交复查 |
| 管理简报 | 本期新增、解决、逾期和复发了哪些问题？ | 切换日报/周报、比较历史、查看来源、导出文本 |

### 判断口径

规则引擎负责计算和结论；当前简报使用模板，不依赖模型服务。未来 LLM 只负责根据已有证据解释事实，不修改数值、责任归属或整改状态。

- **负荷按分钟计算**：每次预计耗时加附加题耗时，再乘对应周期要求次数；总部与区域任务按人合并。
- **周期独立计量**：一次性任务归入截止日期所在周，每日/每周任务分别计算；完成记录只抵扣对应周期的剩余量。
- **区域差异不等于违规**：已确认容量超出属于明确违规；近四个完整周期中位数的 1.5 倍只作为疑似异常参考。
- **数据不完整不下定论**：缺少耗时、频次、逐人分配或负责人时显示数据不足；图表可能只显示已知部分。
- **整改要复查**：回复不直接关单；重新计算后规则不再命中才标记解决，例外到期或问题复发会重新开启。
- **责任与权限分离**：总部任务造成的冲突由总部负责人协调；区域培训角色只处理演示区域内有权限的任务，区域经理只读。

检查范围包括：容量超出、历史异常、截止集中、重复内容、必修覆盖遗漏、临期完成不足、培训师待复核量和关键数据缺失。

### 建议演示路径

1. 打开全国巡检，查看南区人均 **160 分钟**、总部 **100 分钟**与区域 **60 分钟**叠加的示例。容量 **90 分钟**仅为演示配置。
2. 打开问题详情，提交整改措施和承诺日期，再提交复查。未调整计划时，巡检应继续保留问题。
3. 在区域计划中调整任务或为重复安排填写复训理由，保存后观察证据与状态自动更新。
4. 申请例外，使用总部角色审批，再查看例外范围、到期日和处理时间线。
5. 在管理策略中切换「自动提醒（模拟）」，查看按负责人每日合并的站内通知；重复巡检不会产生同日重复通知。
6. 在任务详情登记「本周期完成记录 · 模拟回传」，查看剩余负荷变化。打开管理简报并导出本期结果。

规则、状态与接口说明见 [TRAINING_INSPECTION.md](TRAINING_INSPECTION.md)。

## 功能模块

| 模块 | 已有交互能力 |
| --- | --- |
| 管理看板 | 全国/区域培训指标、积分排行、门店和员工详情、BA 活动状态下钻、任务筛选 |

| 考试 | 组卷、发布、随卷字段与及格规则、任务监控、复核及统计分析 |
| AI 陪练 | 数字人顾客、场景剧本、金句跟读、预览和素材引用 |

| 素材 | 音视频提交、分析结果展示、黄金素材、合集与引用关联 |
| 组织与档案 | 组织架构、门店、人员、账号、BA 照片打卡记录 |
| 界面与配置 | 中文/英文/印尼语切换、品类配置、通知配置原型 |

多语言覆盖既有主要界面；新增培训巡检工作台目前主体为中文，导航已提供英文和印尼语翻译。

## 运行边界与数据

| 当前实现 | 生产接入要求 |
| --- | --- |
| 角色切换与前端范围限制 | 服务端认证、授权与区域隔离；不能信任客户端角色字段 |
| 独立演示任务契约；现有任务摘要标记待补齐 | 任务页与巡检读取同一任务版本，补齐逐人分配、预计耗时、频次、人员归属和负责人 |
| 浏览器开启期间每分钟巡检，任务变化立即重算 | 服务端事件驱动、5 分钟内增量计算与每日全量兜底 |
| 本地站内通知、同日合并、观察模式 | 真实消息中心、幂等发送、客户日历；真实数据观察两个完整周后再启用自动提醒 |
| 模板简报和 mock AI 内容 | 按需接入模型，结构化证据与规则继续作为结论来源 |

巡检状态使用浏览器 `localStorage` 键 `salesboost.training-inspection.v1` 保存，无跨设备同步。清除此键会重建演示数据，也会丢失该浏览器已保存的巡检调整。其他模块仍以各自的 mock 或本地状态为主。

日期统一按 `Asia/Jakarta` 解释，周一到周日为一个周期；响应期限跳过周末，尚未接入地区节假日日历。关闭网页后，本地巡检与提醒不会持续运行。

## 验证

```bash
npm run lint
npm run test:inspection
npm run build
```

- `lint`：TypeScript 类型检查，不会自动改写代码。
- `test:inspection`：15 项规则测试，覆盖周期、任务叠加、数据缺失、覆盖、重复、权限、整改复查、提醒去重、例外到期、完成回传和人员转区。
- `build`：生成 `dist/`；当前仍有较大的 bundle 提示，后续可按页面拆包。

浏览器验证场景包括四个巡检视图、桌面与手机布局、整改回应与失败复查、例外审批、任务调整、提醒去重/已读、刷新持久化和区域权限。验证使用独立浏览器上下文，不需要修改真实业务数据。

```text
src/
  App.tsx                         页面入口、角色与共享状态
  components/                     布局、共用组件与 UI 基础组件
  pages/                          看板、课程、任务、题库、素材与巡检页面
  lib/
    inspectionTypes.ts            巡检统一契约
    inspectionEngine.ts           负荷计算、巡检规则、整改状态转换
    inspectionStore.ts            本地存储、来源适配与定时巡检
    inspectionData.ts             区域、人员、任务和策略演示数据
    inspectionEngine.test.ts      规则与权限测试
    QuestionBankContext.tsx       共享题库状态
    questionBank.ts               题库模型与规则
    materialLibraryData.ts        素材与引用数据
    i18n.tsx                      语言字典与切换
  types.ts                        共用业务类型
```

技术栈：React 19、TypeScript、Vite、Tailwind CSS 4、shadcn/ui / Base UI、Recharts、Lucide React。
