# SalesBoost AI

SalesBoost AI 是面向培训管理团队的后台系统，帮助总部、区域培训负责人和门店管理者完成课程建设、任务分发、练习管理、考试跟踪以及培训质量复盘。

当前版本新增「培训巡检」工作台：它以总部培训负责人的数字分身为定位，持续汇总各区域任务，检查 BA 和培训师的工作负荷，识别任务冲突与覆盖问题，并形成整改闭环。

## 当前能力

### 培训巡检 Agent

- 全国巡检：查看各区域人均计划负荷、P90 负荷、剩余负荷、异常人数和培训师管理压力。
- 区域计划：把总部和区域的学习、练习、考试、采集任务放进同一个周计划，按人查看任务叠加。
- 规则巡检：检查容量超出、历史异常、重复内容、集中截止、必修覆盖遗漏、临期进度、数据缺失和培训师待复核量。
- 整改跟踪：支持待响应、处理中、待复查、已解决和例外生效状态，保留证据、责任人、期限、时间线和复发记录。
- 例外管理：区域负责人可提交例外，总部负责人审批；例外到期后自动重新进入巡检。
- 站内提醒：按责任人每日合并提醒，避免重复发送；逾期事项可升级到总部。
- 管理简报：提供日报、周报、区域对比、问题来源和文本导出。
- 权限演示：总部可调整总部任务，区域角色只能查看本区域和处理自己的区域事项，区域经理为只读角色。
- 本地持久化：演示状态保存于浏览器 `localStorage`，刷新后仍保留任务调整、整改和提醒记录。

### 课程与培训资产

- 总部、区域管理、区域培训和门店多角色仪表盘。
- AI 课件生成、课件管理、数字人顾客、场景剧本和产品金句库。
- 学习任务、练习任务、考试任务和音视频采集任务。
- 题库、组卷、附加题关联和考试复核。
- 组织架构、门店档案、人员档案、BA 打卡记录和素材库。
- 中文、英文、印尼语界面切换。

## 设计原则

培训巡检的判断由确定性统计和规则引擎产生。模型不负责自由判断谁是高风险人员，也不能修改数值、责任归属或问题状态。未来如果接入 LLM，它只根据结构化证据生成说明和管理简报。

任务负荷以预计耗时和实际分配对象为基础。一次性任务按截止日期所在周计量；每日和每周任务按各自周期计量；附加题耗时计入学习负荷。缺少逐人分配、结构化频次、预计耗时或负责人的任务会被标记为「数据不足」，不会被伪造为正常或异常。

历史参考默认使用近四个完整周期。历史不足时只提示需要补齐基线；历史中位数的 1.5 倍只作为疑似异常参考。当前演示数据、容量和区域负责人均为示例，不能直接作为生产管理标准。

## 本地运行

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:3000`。如果 3000 端口被占用，可以指定其他端口：

```bash
npm run dev -- --port 4176
```

## 验证命令

```bash
npm run lint
npm run build
npm run test:inspection
```

`test:inspection` 覆盖任务叠加、周期计算、重复安排、覆盖遗漏、历史异常、数据不足、提醒去重、整改复查、例外审批、权限隔离、完成回传和人员转区。

## 培训巡检文件

- `src/pages/TrainingInspection.tsx`：工作台界面与交互。
- `src/lib/inspectionTypes.ts`：任务、人员、策略、问题单和通知契约。
- `src/lib/inspectionEngine.ts`：负荷计算、规则巡检和状态机。
- `src/lib/inspectionStore.ts`：本地状态、任务同步和巡检调度。
- `src/lib/inspectionData.ts`：演示区域、人员、计划和策略数据。
- `src/lib/inspectionEngine.test.ts`：巡检规则与整改闭环测试。
- `TRAINING_INSPECTION.md`：产品口径、演示流程和生产接入说明。

## 生产接入方向

当前项目主要使用前端 mock 数据。生产化时需要由后端提供统一任务契约、逐人分配、预计耗时、结构化频次、负责人、完成记录、策略版本和例外记录，并将巡检任务迁移到服务端增量计算与每日全量校验。

自动提醒应使用服务端幂等记录，区域权限必须由服务端身份控制。接入真实数据后，建议先观察至少两个完整周周期，校准误报，再开启真实自动提醒。
