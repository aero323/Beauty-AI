# SalesBoost AI

面向总部培训团队、区域培训负责人和门店管理者的培训管理后台。围绕「内容建设 → 任务分发 → 学习与考核 → 问题识别 → 整改复盘」组织工作，覆盖课件、题库、AI 陪练、媒体素材和组织档案。

**当前版本：v0.3.2 · 2026-09-14 — 培训巡检支持在对话里创建自定义巡检需求，并各占一个标签页。**

> 本仓库是可运行的前端交互原型。任务、人员、AI 分析与管理指标以演示数据为主，尚未接入生产身份认证、真实消息服务或持续运行的后端 Agent。培训巡检的规则计算、工作记录、对话回答、发布前模拟与处置留痕可在本地完整验证。

## 本版更新

**审批功能（原型新增）**

- 新增第 6 个角色「审批管理者」：导航含审批中心、待我审批、审批流程配置、审批记录；顶栏铃铛进入全角色的消息中心，未读红点按当前账号统计。
- 培训师产出接入审批（7 类）：课件、学习任务、练习任务、考试、音视频采集任务、数字人顾客、场景剧本在「确认发布 / 保存」时先判断是否需要审批；需要时进入待审批，对学员端与任务下发不可见，审批通过后才生效。题库题目与黄金素材不纳入审批：两处已有轻量人工确认（题库「审核入库」、素材库「确认进入黄金素材」），再叠审批太重，保持各自原有口径。
- 提交审批的角色（总部培训师 / 区域培训师主管 / 区域培训师）新增独立功能页「我的审批流转」：统一查看自己提交的待审批 / 变更待审批 / 已驳回 / 已生效单据，支持撤回与重提；业务模块不再内嵌审批流转分区，只保留提交后的轻量提示。
- 流程配置按「对象类型 × 范围」：全国流程 + 按区域分组的区域流程（未单独配置的区域自动沿用全国流程），候选审批人来自「账号管理」里角色为审批管理者的账号，可多选、任一同意即生效。
- 单据规则：提交后不能直接改内容，可撤回；驳回必须填理由并在同一单据上修改后重新提交；已生效内容的修改会新开变更版本，**老版本在审批期间继续对学员开放**，通过后替换、驳回不影响老版本。
- 通知与催办：提交、同意、驳回、撤回都会写站内信，同时展示 App 推送 / WhatsApp 渠道状态；提交满 24 小时未处理只催办一次，不自动通过、不升级。
- 客户总开关放在 Super Admin 的「系统设置 → 审批功能」：关闭后所有新提交直接生效、已在审单据继续走完，审批流程配置页变为只读。
- 审批中心每个模块右上角带「注」研发标注（数据口径、状态机、通知规则），顶栏「研发标注」开关可一键显示 / 隐藏全站研发标注。
- 审批详情是宽版两栏：左栏看审批信息与流转，右栏直接**预览提交的内容**（课件目录、任务要求、试卷结构、剧本步骤…）与本次变更点；课件目录、附加题与学习任务里的每门包含课件都可点「查看详情」看逐页内容、题目与答案；界面不展示 v1/v2 版本徽标，自己的单据在「我的审批流转」里也不再重复显示提交人。
- 规则引擎与存储：`src/lib/approvalTypes.ts` / `approvalEngine.ts` / `approvalStore.ts`（localStorage 键 `salesboost.approval.v1`，坏存档自动重置演示数据），13 项单测覆盖流程解析、状态迁移、并发与催办。

规则、状态与接口说明（给研发）见 [APPROVAL.md](APPROVAL.md)。

- 培训巡检支持自定义巡检需求：在「和巡检Agent对话」里说「新建一个巡检需求」，Agent 会逐步反问关注方面、范围、周期与起止时间——**每一步既能点选项，也能直接打字回答**（如「重复布置和时间集中都要盯」「只看新品和敏感肌」「南区」「每周一」「从今天起连续 4 周」「确认」）；关注方面里有「包含特定品类」，可以按品类盯——任务已带 新品 / 护肤 / 敏感肌 / 彩妆 / 服务力 / 异议处理 / 销售话术 这些标签，创建后「巡检总览 / 区域负担」后面多一个专属标签页，单独看这个需求的运行情况。
- 培训巡检改为「向管理者汇报 Agent 巡检工作记录」的报告页：标签页收敛为巡检总览与区域负担。
- 总览首屏新增对话 Agent：基于巡检记录回答「最近巡检了哪些任务」「现在有哪些任务需要我处理」等问题，回答都带规则编号与数据来源；本轮由本地确定性规则生成，预留真实模型接入位置。
- 新增巡检工作记录：按批次记录每次巡检覆盖的任务、逐任务结论、新增与解除的风险，结论无变化时合并为同一批次并保留连续巡检次数。
- 自动巡检频次可见可改：「最近一次巡检」右上角显示当前间隔（每 30 分钟 / 每 2 小时），跟 Agent 说「把巡检频率改成每 2 小时一次」即可调整，刷新后保留。
- 结论口径贴近业务：品类覆盖会点名「哪个品类在哪些区域没有任务」（例如「彩妆」只在北区有安排），不再输出「角色不适用」这类结论。
- 学习、练习、考试统一为巡检任务对象，含人员快照、频次、权重、任务关系与执行结果；输出可追溯的 A–F 六类风险。
- 增加音视频采集、素材库与素材引用、BA 打卡记录等培训素材工作流。
- 保留题库资产治理、考试分析、总部 BA 活跃看板和任务监控筛选能力。
- 增加巡检规则测试、移动端导航和本地持久化，并整理功能与生产接入文档。

## 快速开始

建议使用 Node.js 22 或更新版本，配合 npm。项目不需要配置模型 API Key 即可运行演示。

```bash
git clone https://github.com/aero323/Beauty-AI.git
cd Beauty-AI
npm ci
npm run dev
```

打开终端输出的本地地址，默认是 `http://localhost:3000`。若默认端口已被占用，Vite 会尝试其他端口；也可以显式指定：

```bash
npm run dev -- --port 4176
```

生成与预览生产构建：

```bash
npm run build
npm run preview -- --port 4176
```

开发服务默认监听所有网络接口。只需要本机访问时，使用 `npm run dev -- --host 127.0.0.1`。

## 培训巡检 Agent

### 使用入口

以「总部培训师」角色进入左侧 **培训巡检**。桌面端左下角提供角色切换器，手机端通过顶部导航选择工作台。区域演示固定使用雅加达南区。

| 视图 | 管理问题 | 主要操作 |
| --- | --- | --- |
| 巡检总览 | Agent 巡检了哪些任务、发现了什么、下一步做什么？ | 首屏对话 Agent、本次巡检摘要（任务对人的影响结论）、本周期指标卡、巡检工作记录（含异常任务弹窗） |
| 区域负担 | 不同区域的任务给 BA 造成了多少时间负担？ | 区域对比表（人均分钟 / 超载人数 / 单日峰值 / 任务数，右侧「点击查看」进明细）→ 区域明细（任务占用 / 重复内容 / 超载的人）→ 每人每日分钟下钻 |
| 自定义巡检（Agent 创建） | 我自己关心的那类问题，这周给 BA 添了多少负担？ | 在对话里选关注方面 / 范围 / 周期 / 起止时间后生成专属标签页：状态摘要（发现的问题、受影响的 BA、人均分钟、最近一次运行）→ 现在关注到的问题 → 运行记录；到点自动跑，也可「立即巡检」「暂停 / 继续」 |

任务行点「查看详情」看的是只读的任务本身；觉得这条任务排得过重，就在详情里点「向创建者发送调整建议」，由巡检 Agent 生成一封写给任务创建者的站内信草稿（问题、建议动作、影响范围），确认发送后走「消息中心 › 我的消息」（原型只做演示发送）。巡检只给建议，不改任务数据。

### 判断口径

规则引擎负责计算和结论；当前简报使用模板，不依赖模型服务。未来 LLM 只负责根据已有证据解释事实，不修改数值、责任归属或整改状态。

- **负荷按分钟计算**：内容资源预计时长加附加题，再乘周期要求次数；总部与区域任务按人合并成员工级时间轴。
- **周期独立计量**：一次性任务归入截止日期所在周，每日 / 每周任务分别计算；完成记录只抵扣对应周期的剩余量。
- **区域差异不等于违规**：已确认容量超出属于高风险；未确认容量时按历史中位数 × 1.5 作为参考基线，只提示调整。
- **数据不完整不下定论**：缺少预计时长、逐人分配、频次、负责人、推送或回传时输出「数据不足」，缺时长的员工不参与超容量判定。
- **处置要复查**：模拟只给建议；确认处置后递增任务版本，记录操作人、原因、预计影响与重新巡检结果。
- **责任与权限分离**：总部任务需要总部确认或转交；区域培训角色只能调整本区域任务，区域经理只读。

风险分为 A 负荷 / B 时间 / C 人群 / D 内容与任务关系 / E 执行 / F 数据不足六类，每类规则编号可在界面中追溯到阈值与证据来源。

### 对话 Agent

首屏「和巡检Agent对话」支持预设问题与自由输入，回答只复述巡检引擎已有的结论：

| 问法 | 回答内容 |
| --- | --- |
| 最近巡检了哪些任务？ | 最近批次的巡检时间、触发方式、覆盖任务数与逐任务结论 |
| 现在有哪些任务需要我处理？ | 按优先级列出未解决结论，并标注规则编号与影响范围 |
| 风险最高的任务是什么？ | 结论、原因、证据、建议与需要确认的人 |
| 哪些任务数据不全？ | 缺字段的任务与缺失项，说明只输出「数据不足」 |
| 上次巡检到现在有什么变化？ | 两次批次之间的新增、解除与等级变化 |
| 某区域现在什么情况？ | 区域容量基线、人均分钟、超容量人数与命中结论 |
| 某个任务为什么被标记？ | 该任务命中的规则、原因与建议 |

回答一律按当前登录角色的可见范围过滤；问不到的问题返回「我能回答的范围」，不编造结论。本轮回答由 `src/lib/inspectionAgent.ts` 的本地规则生成，接入真实模型时保持 `answerInspectionQuestion(state, actor, question)` 这一个入口即可，界面与工作记录无需改动。

### 建议演示路径

1. 打开巡检总览，首屏 Agent 卡片点「最近巡检了哪些任务？」，看到最近批次的时间、覆盖任务数与逐任务结论。
2. 展开「巡检工作记录」里的任一批次，核对本次巡检覆盖的任务、逐任务结论、新增与解除的风险。
3. 在「巡检工作记录」里点「查看异常任务」，弹窗里能看到这次巡检有哪些任务异常、命中什么、影响多少人。
4. 打开区域负担：先看四个区域的对比表，点进雅加达南区，展开某个超载的 BA 看本周每日分钟构成；想看某条任务本身，就在任务行点「查看详情」，觉得排得过重再点「向创建者发送调整建议」生成一封写给创建者的站内信草稿。
5. 用区域培训主管角色重进页面，确认只看到本区域与全国任务，问 Agent「北区现在什么情况」会被按权限拒绝；切换区域经理角色则为只读。
6. 点右上角「立即巡检」写入一条手动批次，再点「导出工作记录」，导出批次、覆盖清单、风险明细与处置记录文本。

规则、状态与接口说明见 [TRAINING_INSPECTION.md](TRAINING_INSPECTION.md)。

## 运行边界与数据

| 当前实现 | 生产接入要求 |
| --- | --- |
| 角色切换与前端范围限制 | 服务端认证、授权与区域隔离；不能信任客户端角色字段 |
| 统一巡检任务契约；外部任务摘要标记待补齐字段 | 任务页与巡检读取同一任务版本，补齐逐人分配、预计时长、频次、人员归属和负责人 |
| 浏览器开启期间每分钟巡检，任务变化立即重算 | 服务端事件驱动、5 分钟内增量计算与每日全量兜底 |
| 本地站内通知、同日合并、观察模式 | 真实消息中心、幂等发送、客户日历；真实数据观察两个完整周后再启用自动提醒 |
| 审批：本地单据、固定演示审批人、渠道状态模拟 | 单据落库 + 状态机服务端校验（禁止自审）、审批人来自账号与权限系统、站内信 / App 推送 / WhatsApp 接真实消息服务 |
| 模板简报和 mock AI 内容 | 按需接入模型，结构化证据与规则继续作为结论来源 |

巡检状态使用浏览器 `localStorage` 键 `salesboost.training-inspection.v2` 保存，审批状态使用 `salesboost.approval.v1` 保存，均无跨设备同步。清除此键会重建演示数据，也会丢失该浏览器已保存的巡检调整。其他模块仍以各自的 mock 或本地状态为主。

日期统一按 `Asia/Jakarta` 解释，周一到周日为一个周期；响应期限跳过周末，尚未接入地区节假日日历。关闭网页后，本地巡检与提醒不会持续运行。

## 验证

```bash
npm run lint
npm run test:inspection
npm run test:approval

```

- `lint`：TypeScript 类型检查，不会自动改写代码。

- `build`：生成 `dist/`；当前仍有较大的 bundle 提示，后续可按页面拆包。

浏览器验证场景包括两个巡检视图、对话 Agent 的预设与追问、批次展开、任务覆盖清单筛选、处置弹窗提交、区域与只读角色权限、桌面 1440px 与移动端 390px 布局。验证使用独立浏览器上下文，不需要修改真实业务数据，截图保存在 `output/playwright/`。
